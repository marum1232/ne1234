Validate Auth, Users & KYC Routes
What & Why
The auth, users, and KYC routes are the highest-value attack surface — they handle login, registration, OTP, profile updates, and identity documents. Several endpoints currently destructure req.body without schema validation, risking injection, account enumeration, and crash vectors.

Done looks like
Every POST/PUT/PATCH in auth/index.ts and auth/helpers.ts uses validateBody() with an explicit schema from schemas.ts (registration, login, OTP send/verify, password reset, magic link, TOTP).
users.ts endpoints for profile update, role change, file attachment, and account deletion are all guarded with validateBody(). The role field is validated as a strict enum (customer | rider | vendor). The profile update schema caps name at 80 chars, address at 255, and city at 80.
kyc.ts endpoints validate document type as an enum, and all string fields have max() constraints. File fields (base64 strings) are validated for non-empty presence only — actual MIME/size enforcement is handled in the uploads task.
req.query pagination params (page, limit) in users listing endpoints are validated as positive integers with a hard cap (limit max 100).
pnpm typecheck passes.
Out of scope
Admin-side user management routes (covered in the Admin tasks).
TOTP/2FA device management beyond what already exists.
Steps
Audit auth/index.ts and auth/helpers.ts — List every route that reads req.body without .safeParse()/validateBody(). Apply the appropriate shared schema from schemas.ts or define a route-local schema for unique shapes.
Harden users.ts endpoints — Apply validateBody() to profile update, role change, loyalty redeem, and delete-account endpoints. Add validateQuery() for all paginated list endpoints.
Harden kyc.ts endpoints — Apply validateBody() for document submission and status update endpoints. Validate documentType against a strict enum.
Remove unsafe type casts — Replace any req.body as { ... } casts with proper schema-parsed output.
Run typecheck — Execute pnpm typecheck and resolve errors.
